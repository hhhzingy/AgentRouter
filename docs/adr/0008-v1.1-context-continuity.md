# ADR-0008：V1.1 Role/WorkSession Context Continuity

状态：V11-01 已接受（仅确认架构决策；实现、RC 和用户验收尚未完成）。

日期：2026-09-14

基线：`338fcffc001a5ed8e93c00051605f7c6e4eea74a`

## 背景

V1.0 已经持久化 Role、Binding、RoleSession、任务、消息、Artifact 和 native execution，但 WorkSession 切换仍依赖 handoff package/ACK：切换会写 `role_session_handoffs`，目标原生首轮需要文本确认，确认前 Route 工具被阻止。同时，`RoleSession.binding_id` 被当作当前执行绑定的镜像，不能表达一个 WorkSession 在不同 activation epoch 中仍保持同一 Harness/Driver/Native Session 的长期身份。

V1.1 需要让 Role 成为长期身份，让每个 WorkSession 能安全恢复同一原生会话，并在换 Harness 时以可审计的 Portable Context 继承上下文。迁移 001—010 和冻结 Client 合同已经发布，不能通过修改历史字节来实现新语义。

## 决策

### 1. 身份与激活分离

1. `Role.id` 是长期身份；`role_sessions.id` 是永久 WorkSession 身份。
2. WorkSession 的 Harness、Driver、workspace affinity 和 Native Session 在首次成功建立后固定；Native ref 初始可为 NULL，首次成功 receipt 后写入，后续不能因切换或降级静默替换。
3. `RoleSession.binding_id` 不再承担永久 WS 身份。Binding/epoch 是一次 activation/execution authorization；恢复旧 WS、A→B→A 或重新连接都必须创建 fresh activation epoch，并使旧 activation 的异步写入、receipt 和事件失效。
4. 每个 Role 只能有一个可写 Active WS。激活使用锁、preflight 和原子状态变更，任何 live/settling/unknown run 或不确定状态都不能被静默覆盖。
5. 同一 Native Session 的 model/effort 变更必须在同一个 WS/native session 内由 Driver 执行，绝不通过新建 WS 逃避；能力未验证或不支持时安全阻止并给出诊断。
6. 跨 Harness 自动选择只看该 Role 下目标 Harness 的最新 WS；用户始终可以显式新建 WS。workspace affinity、账号/profile 和 native resume 不满足时不能自动复用。

### 2. Continuity 数据模型

1. Core authoritative state 与 Portable Context 分层。前者包括 Role/Charter/权限、项目/组/策略、workspace/worktree/Git、任务/队列/结果/验收、Artifact refs/hash、issue/approval/UNKNOWN、运行 provenance 和已批准配置；注入时保持原样。
2. Portable Context 只收录 Driver 可观察的用户/助手可见内容、Route task/result/notice、工具元数据、小结果、摘要、历史可见片段和 artifact refs；禁止 hidden reasoning、KV、Secret、凭据、环境变量和私有数据库。
3. 以 append-only Context index/head 加上现有 conversation/artifact refs 实现检索和去重，不引入 Vector DB。每条 entry 具备 source WS、source kind/id、content hash 和审计元数据。
4. 已有 WS 恢复发送 Delta `(N,M]`，并排除 `source_work_session_id == target WS` 的 entries；新 WS 发送最大可迁移的完整 Portable Context。两者都随后原样注入最新 Core authoritative state。
5. synced cursor/native history cursor 只能在 Native receipt confirmed 后推进；重试依靠 source key/hash 和 stable marker/history reconcile 幂等，不依赖 LLM 文本 ACK，不重放 route tool、finish 或业务 mutation。

### 3. 容量、压缩与阻止

Context preflight 先读取 Driver 的 capacity/usage，优先调用 native compaction，再重新计算。若仍不足，仅允许对 Portable Context 调用明确的 `ContextCompressionBackend`；压缩结果须记录 provider/model、覆盖范围、输入/输出 hash、token 估计和 fidelity。没有可验证能力或窗口仍不足时安全返回 `CONTEXT_MIGRATION_TOO_LARGE`（或同等明确错误），禁止静默截断。Core authoritative state 永不压缩。

### 4. 删除 WorkSession handoff，保留 task handoff

V1.1 cutover 后停止 WorkSession handoff package、ACK、ACK prompt、`HANDOFF_ACK_REQUIRED` gate 及其 GUI/MCP 产品入口；migration 009 的表、历史行和字节只用于审计，不删除、不新写入、不参与恢复/运行 gate。

`task completion.mode = "handoff"` 是独立的业务语义，必须保留：Core 继续验证目标 `next_request.to`，继续使用 `HANDED_OFF` 状态，UI 继续允许带明确目标和下一步要求的任务。这个 task handoff 不等于 WorkSession context sync。

### 5. Driver 能力与安全边界

Driver 新增的 Context/History/Capacity/Usage/Compaction/ModelSwitch 能力必须逐项给出 evidence-backed 状态：`VERIFIED`、`IMPLEMENTED_UNVERIFIED`、`UNSUPPORTED` 或 `UNKNOWN`。未有协议、版本、探针或 receipt 证据时保持 `UNKNOWN`，不以已有 `open/resume` 代码推断完整迁移能力。

Router 仍只接收受信宿主确认的 native reference、workspace 和 capability 结果；模型/Route payload 不能写 session ref、cursor、KV、Secret 或 OS 路径。

### 6. UI/MCP 表面

管理表面以用户可理解的动作表达：继续已有 WS、新建并继承上下文、目标 Harness、workspace affinity、迁移保真度和可行动的阻止原因。隐藏 cursor、native history cursor、KV、内部 raw budget、hidden context 和 Secret。Participant boundary 保持独立，不因管理 Context sync 获得内部控制权。

### 7. 迁移与发布闸门

只追加 011+；001—010、冻结合同和历史 manifest 禁止改字节。任何新 migration 写入前必须先有 V1.0 upgrade fixture、失败回滚、幂等、备份/恢复和数据保留测试；先验证 fixtures，再写 migration。每一阶段独立提交、测试、报告；V1.1 RC 与用户验收前不合并 main、不打 tag/release。

## 后果

- 需要把当前 binding 级 current 查询、native session save/load、任务派发和 event freshness 改为 activation-aware，同时保留 V1.0 旧数据的只读兼容。
- `conversation_items`、Artifact refs 和 legacy handoff 行继续存在，但新 Context index 需要 source/hash/cursor 以及按 Role/WS 的一致性校验。
- 旧 handoff 测试必须改成“历史可审计、运行时不再写入/不再 gate”的断言；task handoff 需要独立回归，防止删除两者时误伤业务交付。
- Driver 能力不足会显式阻止恢复或压缩，用户会看到迁移保真度/阻止原因；这是可接受的安全结果。
- V1.1 不承诺保存 hidden reasoning、KV、Secret 或不可观察的内部状态，也不通过 Vector DB 追求不可审计的相似检索。

## 非目标

- 不修改 001—010 或冻结 C1/C1R1/C1R1P1 合同字节。
- 不把 WorkSession handoff 历史回放为新的 Context，不删除 migration 009 数据。
- 不扩展 Participant 为 WorkSession 管理者，不在 GUI 暴露内部 cursor/KV。
- 不在没有 Driver/Native receipt 证据时宣称 Codex、Kimi、pi、ZCode 或其他 Harness 的完整 history export/compaction 支持。
