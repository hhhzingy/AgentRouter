# ADR：同一 DeepSeek 后端的有界分段压缩

## 决定

不扩大为 Memory/Vector DB，不静默截断，不自动切换 Provider。显式 owner 配置 `segmentation: { maxSegments, maxTotalInputBytes }` 才启用分段；最多 64 段、总输入最多 64MiB，单请求仍遵守 ApprovedProvider 原有限额。

全量计划阶段按实际 JSON wire 字节、保守 token 上界、输出保留和系统余量切分 entry 边界。每条来源恰好进入一段；单条也超限、总量/段数超限时，首个网络请求前拒绝。当前实现不拆分单条内容，Core 已有大条目引用化继续适用。

每段使用同一后端/模型/受信凭据，串行调用，不自动重试。最终按原顺序组合各段语义摘要和来源集合，不增加另一轮模型合并。所有分段摘要仍是不可信 Portable，最新 Core authority 单独原样注入。跨段冲突不宣称已语义消解，目标须结合时间、来源与当前 authority 处理。

总输出预算先扣确定性容器开销，再分给各段；最后完整序列化复核。任一段失败，整个迁移失败，不返回部分成功、不前移 cursor；成功段的元数据审计保留，原文不删除。

## 限制与后续

保守 UTF8 字节上界不是精确 tokenizer，压力输入若只有字节数不能叫 1M token 实测。分段源集合完整不等于事实100%保留。全流程持久作业/取消、已完成段的可核对恢复尚未实现，不能自动重跑未知结果的作业。
1M token 来源、模型/endpoint 实际边界、目标256K真实续作及引用读取仍需独立证据。
