# 06 协作组合并/拆分安全向导

## 一、原则

- 合并与拆分只影响**未来通信、未来任务、未来规则**，不改写历史；旧组 ARCHIVED 只读；
- **不提供无预检的一键合并**。任何重构必须经过 Preview → blockers 清零 → 用户确认 → 原子 Commit；
- 统一入口 `space.reconfigure.*`（preview/commit/abort/get，CCR-UI-05），UI 不自行拼装迁移逻辑。

## 二、入口

组卡"合并/拆分▾"下拉：合并本组到其他组 / 拆分本组 / 归档本组（归档是普通状态操作 `space.updateStatus`，不走向导）。

## 三、向导步骤（10 步，合并与拆分共用骨架）

```text
1 选择源组        合并: 多选 ≥2 组；拆分: 单选 1 组
2 角色分配        每个角色指定唯一目标组（V1.0 不允许一角色两活跃组）
3 定义目标组      合并: 1 个新组(名称/目的)；拆分: ≥2 个新组
4 新规则          每组交接要求/完成定义/并行说明（生成新 policy revision）
5 工作区策略      每组 workspace_strategy + 映射；明示"合并不合并 worktree"
6 队列处置        逐项选择未开始任务的处置（§五）
7 会话策略        每角色选择会话连续性（§六）
8 Preview         space.reconfigure.preview → blockers / 影响面 / 确认项
9 用户确认        逐项勾选 required_confirmations，输入组名二次确认
10 Commit         space.reconfigure.commit（plan_id+plan_hash+revision+租约）
                  进度条 → 结果页（新组/归档组/处置清单）
```

步骤 1-7 任何修改都使 Preview 失效，回到步骤 8 必须重新 preview（plan_hash 绑定全部输入）。

## 四、Preview 页（核心）

```text
┌─ 预检结果 ─────────────────────────────────────────────┐
│ ⛔ 3 个阻断项（必须处理后才能提交）                       │
│  1. Run #412 (周实现) 正在 RUNNING —— 组内存在活跃 Run    │
│     [等待完成] [取消 Run]                                │
│  2. Run #409 (陈复核) 状态 UNKNOWN 未对账                 │
│     [去对账]                                             │
│  3. 唐测试 账号切换进行中                                 │
│     [等待切换完成]                                       │
│────────────────────────────────────────────────────────│
│ ⚠ 2 个警告（可继续，需确认）                              │
│  1. 队列中 2 项任务将 SUSPEND_FOR_REVIEW（默认）          │
│  2. 林岚 选择 NATIVE_RESUME，Adapter 认证支持 ✓           │
│────────────────────────────────────────────────────────│
│ 影响面: 角色 6 · 活跃 Run 1 · 排队任务 2 · 会话 6 ·       │
│         工作区 2 (wt:core, wt:ui 不合并) · 新规则 r(new)×2│
│ plan: a91f…c3 · revision 47                              │
│                              [中止] [重新预检] [提交]     │
└──────────────────────────────────────────────────────────┘
```

Blocker 判定（与协议一致）：

- 组内存在 RUNNING / STARTING / WAITING_APPROVAL / SETTLING Run；
- 存在 UNKNOWN 且未对账 Run；
- 存在未完成账号切换；
- 工作区资源租约不确定；
- 新规则未通过验证；
- 存在未分配目标组的角色；
- 存在未选择处置的排队任务；
- 会话连续性策略未明确。

每个 blocker 给出去处链接（跳角色详情/对账面板），处理后可"重新预检"。**不存在"忽略阻断继续"按钮**（sc-23）。

## 五、队列处置（步骤 6）

逐项列出未开始任务，每行四选一（默认 SUSPEND_FOR_REVIEW）：

| 选项 | 含义 |
|---|---|
| MOVE_WITH_ASSIGNEE | 随执行角色进入目标组 |
| SUSPEND_FOR_REVIEW（默认） | 挂起，事后人工复核 |
| CANCEL | 取消并记录原因 |
| KEEP_IN_ARCHIVED_GROUP | 仅历史保留，不再自动执行 |

**正在等待下属结果的任务不能静默迁移**：单独分组列出，必须先完成、取消或转人工（sc-23 含此类 blocker）。

## 六、会话策略（步骤 7）

| 选项 | 说明 | 默认 |
|---|---|---|
| NEW_SESSION_WITH_HANDOVER | 新会话 + 完整交接包（最稳定） | ✓ 拆分强制此项 |
| NATIVE_RESUME_WITH_TRANSITION | 仅 Adapter 已认证支持且用户显式选择 | 合并时可按角色选 |
| KEEP_ARCHIVED_ONLY | 旧会话只读，不再执行 | |

拆分不宣称旧角色"已遗忘"其他组信息：向导中文案明示"历史对话你可查看，但不会自动送给新组其他角色"。

## 七、Commit 与结果

- commit 携带相同 `plan_id + plan_hash + expected_revision + controller lease`，事务性提交；
- 进度页分步展示：Drain 停止新派发 → 处置队列 → 原子提交 → 发布新规则与章程 → 创建/恢复会话并发送 Group Transition Packet → 恢复派发；
- 结果页：新组链接、归档组链接、每个角色的会话策略执行结果、失败时的整体回滚说明（不做部分迁移）；
- 交接包内容（role_id、旧/新组、生效时间、新组通讯录、新规则版本、更新后职责/权限/工作区、未完成任务处置、已确认项目事实、下一步、不可自动继承的旧假设）在结果页可逐角色查看。

## 八、中止

任何阶段可 `space.reconfigure.abort`；已 Drain 的组在中止后恢复派发。中止与失败都产生系统事件进时间线。
