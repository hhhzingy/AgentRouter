┌──────────────────────────────────────────────────────────────────┐

├───────────────┬─────────────────────────────┬────────────────────┤
│ 左栏: 身份     │ 中栏: 对话与 Route 事件      │ 右栏: 当前状态      │
│               │                             │                    │
│ · 角色章程卡   │ [系统卡] 角色章程 r2 · 已交付 │ · 当前任务          │
│ · 职责/非职责  │ [用户] 请完成登录接口        │ · Run 状态          │
│ · 当前组/通讯录│ [Route] →陈复核 复核请求     │ · 队列 (2)          │

窄窗口（<1100px）折叠为页签：身份 / 对话 / 状态。

## 二、左栏：身份与配置

| 区块 | 内容 | 数据 |
|---|---|---|
| 身份 | 展示名（可改 `role.rename`，改名不改 ID）、role_id 短码、角色类别 | `RoleVM` |
| 当前组 | 组名 + 同组联系人头像列表（点击跳对应角色） | `SpaceVM` + `role.list` |
| 章程摘要 | 使命、职责、非职责、当前 revision；点击看完整章程卡 | CCR-UI-04 |
| 运行配置 | Harness · Provider Profile · 模型 · 推理强度（含 source/availability 徽标） | CCR-UI-02/07 |
| 工作区 | 路径、read_only/read_write、共享策略 | CCR-UI-06 |
| 有效权限 | **只显示实际授予**，请求历史折叠 | CCR-UI-07 |
| Binding 历史 | 当前 Binding epoch + 历史绑定列表（换 Harness 不删旧会话） | `binding.getCurrent/listHistory` |
| 队列 | 排队任务列表 + 位置，可取消（`task.cancel`） | `task.list` QUEUED |

## 三、中栏：对话与 Route 事件（含章程第一条系统卡）

**角色章程永远是对话流第一条**，系统卡样式，不伪装成用户消息：

```text
┌─ ⚙ 系统 · 角色章程 (r2) ─────────────── 已交付 09:58 ┐
│ 身份: 周实现 (执行)        协作组: 核心实现组           │
│ 职责: 实现合同和核心服务…                              │
│ 不负责: 不设计最终 UI…                                 │
│ 同组角色: 林岚(规划) 陈复核(复核)                       │
│ 工作区: ⧉wt:core (read_write)                        │
│ 有效权限: read_write · 网络 provider_only              │
│ 模型: pi/deepseek-v4-pro · 推理 high                   │
│ 项目规则: r5 · Route 协议摘要                          │
│                          [查看完整章程] [历史版本]      │
└───────────────────────────────────────────────────────┘
```

- 未交付成功（DeliveryState != DELIVERED）：卡片显示"章程交付中/失败"，角色状态"待初始化"，输入框禁用（Bootstrap 未完成不派首任务）；
- 章程更新（换组/职责/权限/模型变化）发布新 revision，对话流中插入新的章程系统卡（不覆盖旧卡）。

对话流条目（`conversation.read`，ConversationItemKind）：

| Kind | 渲染 |
|---|---|
| USER_MESSAGE | 用户气泡 |
| ASSISTANT_MESSAGE | 角色气泡 |
| TOOL_CALL / TOOL_RESULT | 可折叠工具卡：工具名、状态、摘要；默认折叠参数 |
| ROUTE_TASK | Route 卡：`→ 陈复核「复核请求」`，点击跳任务 |
| ROUTE_RESULT | Route 结果卡：带 Acceptance 状态 |
| NOTICE | 细体系统行，不强调（普通通知不唤醒） |
| APPROVAL | 审批卡内嵌决定按钮（Controller 限定） |
| SYSTEM_EVENT | 系统行：组变更、Binding 切换、账号切换 |
| **GAP** | 缺口卡：`⚠ 10:02–10:07 历史缺失（接口无法补取）`，明示不可恢复，不静默跳过（sc-27） |

红线：

- 不渲染模型私有思维链；
- 发送用户输入（`conversation.sendUserInput`）后只显示"已送达"，**不产生"已读/已处理"回执**；
- 角色忙时输入框下方常驻"新消息将进入队列"提示；
- `sensitive` 标记条目不渲染内容体，只显示"已脱敏"占位。

## 四、Route 交互可视化

同组角色间的任务派发/结果交付在中栏以 Route 卡呈现，并在对话流顶部提供"协作视图"开关：仅看 Route 事件（跨角色任务链）。跨组通信不存在 UI 入口；若 Core 拒绝了越界调用（Mock sc-07），以 SYSTEM_EVENT 呈现"跨组通信被拒绝（组隔离由 Core 强制）"。

## 五、右栏：当前状态

| 区块 | 内容 | 红线 |
|---|---|---|
| 当前任务 | Task 卡：摘要、TaskState、完成去向、blockedReason | Task 状态独立一道 |
| Run | RunState、开始时刻、时长、nativeSessionDisplay、exitReason | 与 Task 状态分行显示，SETTLING 显示"正在收尾"而非"完成" |
| UNKNOWN | reconciliationRequired=true 时显示对账面板（`run.reconcile` 六动作 + 证据上传） | UNKNOWN 不自动重跑 |
| 审批 | 该角色 PENDING 审批列表 | 决定进审批卡 |
| 产物 | 该角色任务链产物，校验状态 | `artifact.*` |
| 组变更 | 成员历史：何时入组/离组/随重构迁移 | CCR-UI-10 |
| Binding 历史 | epoch 列表、切换原因 | `binding.listHistory` |

## 六、状态合成展示位

头部状态灯按 07 §四优先级合成（需介入 > 待审批 > UNKNOWN > 执行 > 收尾 > 等待 > 排队 > 暂停 > 空闲），"最近完成"仅以 `✓` 辅助角标出现 10 分钟，绝不覆盖主状态（区分"角色空闲"与"最近完成一项任务"）。
