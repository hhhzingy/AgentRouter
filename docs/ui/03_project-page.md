# 03 单项目页

## 一、原则

项目页**以组和角色为中心**，不是全局菜单的换个壳。进入项目后，用户 80% 的时间应在"概览"页签完成：看组、看角色状态、点进角色、派发任务。

## 二、项目头部

```text
┌──────────────────────────────────────────────────────────────────┐
│ ← 支付中台重构                          ⌁ SSH · core-prod-01      │
│   ~/work/pay-core  ·  ⎇ main ✓  ·  自动派发:开  ·  ▶2 活跃 Run   │
│                                                                   │
│   [概览] [协作组与角色] [时间线] [收件箱●2] [审批与问题⚠1] [产物]  │
│   [模型与账号] [设置]                       ＋创建协作组  ⇪导入方案 │
└──────────────────────────────────────────────────────────────────┘
```

| 元素 | 数据 | 备注 |
|---|---|---|
| 项目名/返回 | `ProjectVM.name` | 返回首页 |
| Core 与路径 | `hostLabel` / `displayRoot` + `ConnectionState` | 断开时显示连接徽标，页面只读化 |
| Git/目录状态 | 提案字段（CCR-UI-01） | `⎇ main ✓/有改动/非 git 目录` |
| 自动派发 | `runtime.pauseDispatch/resumeDispatch` | 项目级开关态需 CCR（暂归入 CCR-UI-01 项目扩展信息） |
| 活跃 Run | `activeRunsCount` | 点击筛选时间线 |
| 页签未读 | inbox/issues/approvals 计数 | 红点 = 需要用户，灰点 = 仅新增 |
| 创建协作组 | `space.create` → 编排流程 | 主按钮 |
| 导入方案 | `/projects/:id/plan?source=import` | 次按钮 |

## 三、概览页签：协作组卡片

协作组是第一视觉单元。项目较小时卡片式（2 列），角色 >12 或组 >6 时可切列表/看板。

```text
┌─ 核心实现组 ─────────────────────────── r3 · ⧉wt:core ─┐
│ 目的：Core、协议、SSH 与稳定性                          │
│                                                         │
│  ●林岚      ●周实现        ◐陈复核                      │
│  规划       登录接口(运行中)  等待复核结果                │
│  空闲       Run #412        队列1                        │
│                                                         │
│  ⚠1 待介入   ⧉2 排队   最近交接: 周实现→陈复核 10:52     │
│                                                         │
│  [派发任务] [合并/拆分▾] [组详情]                        │
└─────────────────────────────────────────────────────────┘
```

组卡字段：

| 字段 | 来源 | 说明 |
|---|---|---|
| 组名/目的 | `SpaceVM.name` + 提案 purpose（CCR-UI-10） | purpose 展示在组名下一行 |
| 组规则 revision | 提案 `policy_revision`（CCR-UI-10） | 小字 `r3`，hover 看规则摘要 |
| 工作区 | 提案 WorkspaceVM（CCR-UI-06） | `⧉wt:core`，与组名同行永远可见 |
| 角色行 | `role.list`（Scope=space） | 头像+名+当前任务摘要+状态（07 §四合成） |
| 活跃任务 | `task.list` ACTIVE | 角色名下行即其 ACTIVE task summary |
| 排队 | `SpaceVM.queuedTasksCount` | |
| 待介入 | `issue.list` 按 space 过滤 | |
| 最近交接 | 时间线 HANDED_OFF/ROUTE_RESULT 最新一条 | |
| 合并/拆分入口 | → `/spaces/:id/reconfigure` | 下拉：合并到其他组 / 拆分本组 / 归档 |

### 组 ≠ worktree 的界面表达

- 组卡右上角永远同时存在"组规则 rN"与"⧉工作区"两个徽标；
- 两个组共享同一工作区时，工作区徽标变 `⧉共享·串行写`（shared_serial_write），Tooltip 解释"同一物理工作区同时只有一个写 Run"；
- 合并向导中明确提示"合并不合并 worktree"（06 §四）。

### 活跃任务条（概览顶部）

```text
▶ 进行中 2 · 周实现「登录接口」Run#412 12:31 ─ 苏界面「设置页」Run#415 03:12
```

横向滚动条，点击进入对应 Run（角色详情定位）。

### 最近交接条

```text
⇄ 周实现 → 陈复核「登录接口复核」 10:52 · 陈复核 → 用户「不通过结论」 11:03
```

## 四、协作组与角色页签

- 左：组列表（含 ARCHIVED 组，灰显"已归档 · 只读"）；
- 中：组详情 —— 角色组织、通信边界说明（"仅组内可互相派发"）、组规则、工作区、活跃任务、组历史（成员变更/规则版本）；
- 组历史数据依赖 CCR-UI-10（membership history / policy revisions）；
- 归档组点击进入只读历史视图：可查看旧对话与任务，禁止派发（任务和消息锁定创建时组与规则版本）。

## 五、其余页签

时间线 / 收件箱 / 审批与问题 / 产物 / 模型与账号 / 设置 —— 见 `01_information-architecture.md` §六~§十一。项目页内全部页签共享同一 Scope=projectId。

## 六、派发任务（项目页内的轻量入口）

组卡"派发任务"与角色详情"发消息"统一打开派发抽屉：

```text
┌─ 派发任务 ──────────────────────────┐
│ 给: [周实现 ▾]  (协作组: 核心实现组)  │
│ 摘要: [________________________]     │
│ 详情: [________________________]     │
│ 完成后交给: (●) 我  ( ) 同组角色[▾]   │
│                                      │
│ 该角色正在执行 Run #412              │
│ 此任务将进入队列，位置 2              │
│              [取消]  [派发到队列]     │
└──────────────────────────────────────┘
```

红线落地：

- **结果去向必选**（用户/同组角色），无默认广播 —— "结果只交显式对象"；
- 角色忙时明确告知排队位置（`TaskVM.queuePosition`），不说"稍后执行"；
- 角色空闲时按钮为"立即派发"，忙时为"派发到队列"，文案随状态变化；
- 跨组角色不出现在"同组角色"下拉中（组隔离 UI 层第一重表达，Core 强制为最终防线）。

## 七、项目页空状态

| 场景 | 结构 |
|---|---|
| 无协作组 | 大空态：创建协作组 / 导入编排方案 双按钮（01 §十二） |
| 组内无角色 | 组卡内空态 + "打开编排" |
| 有组有角色无任务 | 概览顶部引导条："给任意角色派发第一项任务"，附最近编排方案快捷入口 |
