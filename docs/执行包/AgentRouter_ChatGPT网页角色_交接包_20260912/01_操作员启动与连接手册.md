# 操作员手册:启动与连接(人执行,非 ChatGPT)

## 前置

- 本机 AgentRouter Core 运行中(数据目录下有 endpoint.json);
- 目标角色已存在(如无,先用管理面/执行包流程建角色与 Role Plan);
- Tailscale 已登录。

## 步骤

1. **启动参与者 HTTP 入口**(在 integration 目录):
```
node --experimental-strip-types apps/participant-mcp/http.mjs .local/management-live/core <角色ID> --gen-token --port 8790
```
   首次运行会在数据目录生成 `participant-token.txt`(权限 600)。记下启动输出里的端口。
   注意:用 `node --experimental-strip-types` 直接跑 TS 版;或先 `node tools/build-participant-http.mjs`(如已提供)再跑 bundle。

2. **挂私网 HTTPS**(Tailscale Serve,自动带 tailnet 鉴权与证书):
```
tailscale serve https 127.0.0.1:8790
```
   得到一个 `https://<机器名>.<tailnet>.ts.net` 形态的 URL。

3. **在 ChatGPT 侧配置连接器**(需要账号具备 MCP/连接器权限):
   - 连接器类型:自定义 MCP(Streamable HTTP);
   - URL:上面的 ts.net URL;
   - 认证:Bearer token = `participant-token.txt` 内容。
   若账号没有连接器/MCP 权限:**只挂起该用例**(BLOCKED_BY_HOST),不要绕过。

4. **验收闭环**(与 ChatGPT 对话完成):
   - ChatGPT 列工具(应恰好 3 个)→ 读收件箱 → 操作员给出已审核文本 → ChatGPT 调 `participant_register_artifact` → ChatGPT 回报 `artifact_id`+`sha256`。

5. **操作员核验**(本地):
   - 工作区 `agentrouter-artifacts/<name>` 存在且内容一致;
   - Core DB `artifacts` 表有该 `sha256` 的 AVAILABLE 行;
   - 以上都满足才算网页角色闭环 PASS。

## 停止与清理

- Ctrl-C 停 HTTP 入口;`tailscale serve --https=443 off` 撤销暴露;
- token 轮换:删除 `participant-token.txt` 后用 `--gen-token` 重启。

## 安全性质

- 绑定默认 127.0.0.1(加 `--allow-remote` 才绑 0.0.0.0,一般不需要——Tailscale Serve 做桥);
- Bearer token + Tailscale 身份双层;泄漏即轮换 token;
- 写路径由 Core 从角色绑定工作区推导,客户端不可指定路径。
