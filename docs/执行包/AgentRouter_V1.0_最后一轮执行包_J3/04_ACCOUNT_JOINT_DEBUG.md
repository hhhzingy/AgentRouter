# 真实账号联合调试

## 1. 先分开两个身份体系

开发 AgentRouter 的 Codex 是“开发控制端”；AgentRouter 启动的 Codex/Kimi/pi 是“被测执行端”。两者不能共享本轮切换操作所影响的认证缓存、托管进程、数据集和恢复目录。不得在开发 Codex 的活跃账号目录内执行 A/B 替换；不得按 `codex.exe`/`node.exe` 名称全局杀进程。

已有原生账号只可在用户同意后登记。原始 secret 不给开发模型阅读；连接器、聊天、GitHub Issue 和截图均不能作为凭据传递渠道。

## 2. H-01：第一次一次性向用户收集什么

Codex 先盘点可读取的非秘密环境信息，已知仓库路径、设备和 SSH alias 不重复询问。仅收集尚缺的项目：

| 项目 | 用户需要确认 | 不应索取 |
|---|---|---|
| Codex | 测试 Profile A/B、允许登录的主机与用途；是否影响日常会话 | auth.json、Cookie、Refresh Token 正文 |
| Kimi Code | 两个可用于切换验证的 Profile，登录由用户执行 | OAuth 缓存、访问令牌 |
| pi | 一个明确 Provider 和可用模型，配置由受控入口完成；必要切换 Profile | 把 API Key 发到聊天或命令输出 |
| 费用 | 该轮总预算/每次上限/允许模型、遇不足是否暂停 | 无限额度默认许可 |
| Ubuntu | 现有 host alias、已核对指纹、远程临时路径、服务安装范围 | 私钥内容或 root 密码 |
| 现场 | 原生对话框/输入法/睡眠测试、干净 Windows 测试条件 | 让用户代替 Codex 完成全部工程测试 |

账号别名与 Profile ID 不是账号认证原文。只在用户本地确认实际身份，不把真实邮箱、组织 ID 和绝对凭据路径提交 Git。没有第二账号就明确阻断 A/B 用例，不能用同一账号改标签冒充切换成功。

## 3. 开放真实网络前的安全门

执行并保存 SG-1—SG-3：静态扫描；假 Provider 捕获；canary 对抗。开发工具、受控 Agent Shell、文件工具、插件、MCP 和网络出口逐项验证，不能仅验证其中一个。

假 Provider 检查 Key 仅出现在认证传输层，消息/system/user/tool/result/异常中没有 secret；转发器禁止任意目的地、跨域重定向和返回凭据。认证进程与工具进程的权限差异须实际证实；同 UID、可读环境或可调试父进程时，不得宣布硬隔离通过。

原生身份存储可以是文件或 OS keyring。先查当前版本实际能力，不能假设 `CODEX_HOME` 独立就连 keyring 也独立。账户服务设计要同时保留 F18 的文件型最新凭据快照语义和受控登录方式。源码已存在 switchAccount 抽象，但真实存储/核验仍需实现（来源 S06/S12；官方补充 S23）。

## 4. 每家每个平台的首次真实闭环

(1) 用户在原生登录/受控配置界面完成认证，Codex 不捕获输入。

(2) 软件报告实际登录状态、脱敏身份、Harness 路径/version/hash、Provider 与真实模型列表。未登录/未授权/版本不匹配分开显示。

(3) 在无敏感内容的临时工作区执行一个限额任务：读取固定测试文件、调用一个获准工具、输出指定格式、通过 route_finish 交付固定小文件；核对文件真实存在和 hash。

(4) 验证工具审批的允许和拒绝、任务取消、进程停止、历史回看。不能只要求模型输出一个字符串就把工具/协作/取消均计通过。

(5) 切回 GUI 主流程，确认任务状态、原生轮次状态、发布状态、用户验收状态独立；不新增收货回执唤醒。

(6) 保留脱敏证据；临时低额度 Key 是否撤销、长期测试 Profile 是否保留，由用户选择并记录。测试收尾撤销临时 Key 不等于删掉用户日常账号。

## 5. A→B→A 切换试验

先在隔离数据集执行，记录受影响 auth_unit、role、binding epoch 与 owned process group。

- A 有活跃任务时申请 B：仅相关 auth_unit 停新派发；UI 显示影响对象，允许用户选择等待当前轮次或显式取消。其他无关联角色不应被全局暂停。
- 旧进程未停止不得 installTarget；软取消超时走已验证的进程族终止，无法证明资源停止则 UNKNOWN/QUARANTINED，不能强行释放。
- snapshotLatest 保存的是运行后的最新认证状态，不是最初导入副本。验证刷新路径应使用真实可观察的刷新或确定性注入端口+受控存储故障，明确证据类别，不能凭文件 mtime 宣称服务端 Token 已刷新。
- 安装目标 B 后，从对应原生认证接口核对身份。身份与目标不符必须 FAILED_SAFE，绝不继续业务。
- B 完成一项真实小任务，再切回 A；核对历史和绑定映射、最新凭据、模型/Profile 归属，旧 epoch 回调不污染新运行。
- 在 REQUESTED/PAUSING/QUIESCING/SNAPSHOT_OLD/INSTALL_TARGET/VERIFYING/COMMITTED 等持久阶段分别注入进程退出。部分阶段只用假凭据做故障注入；真实凭据试验采用安全、可恢复的子集，分开标注，不对生产账号做损坏攻击。
- 窗口关闭、Core 重启、认证失效、取消登录和网络失败均须收敛到明确状态。APP 重新打开不能盲目恢复旧任务或切换未完成身份。

Kimi 原生恢复与新会话交接分别实测。pi 使用 Provider/Profile 能力，不套用 Codex auth.json 逻辑；不承诺 pi 有统一套餐额度。

## 6. 费用与额度

本轮默认每个 auth_unit=1 活跃运行。实际模型从 Provider/原生接口发现，不把聊天中旧模型名写死。软件记录模型可用性来源和查询时间；quota=UNKNOWN 不能视作无限。

硬费用上限只有相应 Provider/受控 Broker 提供并实测时才可声称。其余为本地软预算与启动预算：发起前限制次数/token/模型，接近预算停止新请求并提示；在途请求可能仍收费，必须说明。401/403/429/网络重试不自动切到另一个收费账号，不用多账号绕过服务限制。

## 7. 记录与异常联络

一项用户配合请求写明 request_id、当前提交、影响 Test ID、只需用户做的步骤、许可对象、预算、风险与回退。用户完成后 Codex 接着运行检查，不能要求用户把最终结果再送回网页。

发现真实 secret 出现在模型输入/日志/截图/仓库时立即停相关工作、隔离证据、直接通知用户撤销/轮换；清理 Git 历史或远程数据是单独授权动作，不静默删除。
