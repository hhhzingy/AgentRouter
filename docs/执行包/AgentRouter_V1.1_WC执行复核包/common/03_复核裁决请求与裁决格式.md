# 复核裁决请求与输出格式

请复核者对下列 6 个裁决点逐一输出 `ACCEPT / ACCEPT_WITH_CONDITIONS(条件) / REJECT(理由)`：

1. **WC01 引擎架构**：持久 intent + 事务外网络调用 + 短事务提交 + SEEDED 恢复，是否满足
   "最小修复而非泛化重写"约束（SH-03）？"seed 提示注入即目标初始化"的 fixture 实现是否可作为
   真实通道接线前的验收载体？
2. **WC02 替代分支选择**：在 backend 未做 warm 驻留前，"显式 UNSUPPORTED + 不暗换 ref +
   preflight 引导新 WS"是否被接受为合规中间态（复核裁决 3 的两个选项之一）？
3. **WC05 抖动判定**：kimi 三点二分（81777d4 PASS / 9796f98 FAIL / 108b70a PASS）+
   fa62a1b 三连 FAIL，判为模型行为而非代码回归——证据链是否充分？是否要求补充
   （如同一 SHA 多次重跑的通过率数据）？
4. **WC03 Origin 策略**：默认仅 loopback+端口精确匹配、跨网显式 allowedOrigins，
   是否满足 W-02 的"真实 HTTPS 路径"要求（tailscale serve 场景）？
5. **W-05 持久化策略**：以 application_audit（principal+project.create）恢复自创建可见，
   是否可接受（对比：独立映射表迁移 vs 审计派生）？注意未外溢验证已在用例中。
6. **WC06 分阶段**：冲突定位已完成但组合 SHA 未出，是否接受"SC1 先行、组合分支随后"的顺序，
   还是要求先出组合 SHA 再复核本包？

输出格式（单行 JSON，逐点）：
`{"verdicts":{"1":"...","2":"...","6":"..."},"blocking": [...],"non_blocking":[...],"next_commands":[...]}`
