# 架构与 MCP V1 工具

```text
Dev Codex
  -> STDIO MCP: agentrouter-mcp
  -> AgentRouter Client API (agentrouter-client/1)
  -> LOCAL_CORE
  -> SQLite / projects / roles / tasks / adapters / API registry
```

MCP是薄适配层：不直连SQLite，不绕过Client API，不直接启动Harness，不维护第二套状态机。

## V1工具
读：
- router_status
- router_project_get
- router_roles
- router_role_get
- router_conversation
- router_task_get
- router_results
- router_issues
- router_models
- router_events

控制/写：
- router_control_acquire / router_control_release
- router_plan_validate / router_plan_apply
- router_role_charter_update（capability存在才注册）
- router_task_dispatch
- router_task_cancel / router_run_cancel
- router_result_accept / router_result_reject
- router_wait（单次<=30秒）

写操作必须带稳定 request_key，映射Core operation_id。同request_key不同payload应冲突。不要使用MCP JSON-RPC request id作为业务幂等键。

成功派发只返回必要task id/state，不产生“对方已接收/已处理”的业务回执。
