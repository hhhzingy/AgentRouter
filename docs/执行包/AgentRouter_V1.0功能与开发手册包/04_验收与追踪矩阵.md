# AgentRouter V1.0 验收与追踪矩阵

日期：2026-09-09。本文是**计划用例，不是执行报告**。所有现场、应用集成和打包用例初始状态均为 `NOT_RUN`。本包的离线规范检查单独记录，不替代这些用例。

## 1. 执行规范

每条测试记录：测试 ID、功能 ID、阶段、实际环境与依赖版本、前置状态、操作、预期、实际结果、退出码、脱敏证据路径、执行时间、测试者，以及 PASS／FAIL／BLOCKED_ENV／NOT_RUN。没有凭据或 Windows 环境时写 BLOCKED_ENV，不能伪造 PASS。

单元/集成用可控模拟器；原生行为用固定版本真实 Harness；Windows 进程、路径、托盘与打包必须在目标平台测。对确定性缺陷先固定最小复现再修复，回归测试不可删除。关键不变量缺陷是发布阻断项。

## 4. 发布门槛

F01—F25 的适用测试应通过；F26 验证边界预留且没有外部功能误开放。三家 Harness 均须通过公共契约和各自现场测试，不能以“演示成功”或“实验标签”替代。任何消息丢失、错身份、未知操作自动重跑、遗留写进程、秘密泄露、固定版本漂移属于阻断。

先完成阶段 Gate，再进入依赖阶段；不依赖现场环境的工作可以并行，但受阻的发布能力不能标为已完成。已知限制只用于真实约束，不用于掩盖违反既定协议的缺陷。

## 5. 推荐证据文件

`evidence/<test-id>/<run-id>/` 保存环境摘要、输入固定样本、命令退出码、事件片段、前后数据库摘要、必要 UI 截图和人工核对结论。认证文件、API key、刷新 token、工具桥 token 不入证据仓库。截图也需脱敏。
