# J3-01/03/04/05：真实执行链路，不用新增大架构

## 目标链路

GUI → 现有 Client API → ApplicationService/ExecutionCoordinator → NativeBackend registry → 实际 Harness 进程 → 已批准 Provider → Route 内部工具 → 结果/产物 → 原生收尾 + 本次运行资源安全 → GUI。

必须从与最终产品一致的入口运行；不能只在 tests 目录另造 live script，产品入口继续 NO_EXECUTOR。

## 后端注册和配置

每个 Binding 要固定：实际可执行路径、版本、Harness、Profile 引用、模型 ID、推理值、工作区、权限配置和运行代次。
注册不能只凭文件存在声明 LIVE_TESTED；读取、执行、工具、取消、恢复分别记录。
终端上成功并不代替 App Server/ACP/RPC 接入成功。直接 OpenAI-compatible HTTP 请求不算 pi。

## 实施清单

1. 将 FixtureDriver 保持为受控测试兼容路径；生产入口注册 NativeBackend，禁止 fallback 到 Fixture。
2. 身份、账号引用和权限由可信 Core/监督器绑定。模型不能通过 payload 自称账号或提交 supervisor 成功证明。
3. 接现有六个内部 Route 工具，保持 role/run/epoch 身份；普通通知不唤醒，结果只交明确对象。
4. Codex：锁定实际二进制与其 Schema；接会话、轮次、消息、工具与审批事件；反向请求不默认全允许。
5. Kimi：基于当前 kimi-code 的 ACP 初始化协商，处理逆向请求、取消、会话恢复；不能混用旧 kimi-cli 的命令和目录。
6. pi：RPC 子进程与受控扩展；agent_end 不算结束，agent_settled 才是原生结算证据之一。
7. 支持登录和模型状态查询，但返回脱敏对象，不返回认证原文。
8. 统一错误分类：NOT_IMPLEMENTED / ENVIRONMENT / PERMISSION / AUTH_EXPIRED / MODEL_UNAVAILABLE / RATE_LIMIT / NETWORK / AMBIGUOUS；不能全部变成登录失败。
9. UI 必须显示绑定的是 LIVE Harness 还是 Fixture；不存在明确真实证据就不改认证等级。
10. 修正 build:win/打包入口，构建清单绑定 source SHA；测试与安装包必须装入同一条生产链。

## 收尾边界

原生终态、操作完成和进程退出不是同一个概念。保留当前“每轮独立进程并恢复会话”的方案时，必须证明本轮相关工作进程已停止才释放写资源。
若以后选择常驻 App Server，不得等一个设计上永久存活的进程退出；必须先 ADR 和测试证明该轮工具与写权限已撤销/收尾。当前不得为跑通而取消已有屏障。

## 安全阻断不妨碍离线实施

ACL 未过时仍可完成后端注册、握手、无秘密协议测试、Mock Provider、错误映射、超时、六工具、模型目录与 UI。只有将真实凭据交给被测运行路径这一步受安全 Gate 限制。
