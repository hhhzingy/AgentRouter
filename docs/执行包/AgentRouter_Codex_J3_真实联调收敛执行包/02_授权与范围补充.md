# 更新 H-01：不重复索要已给出的信息

本节是用户将工作包交给 Codex 后采用的执行规则；本包没有自行修改仓库 H-01。

## 已明确的条件

- 本轮 Windows 本地完整调试、记录、修复与优化。
- 预算：不设费用上限。不再询问总预算和单次金额。
- 仍使用小任务、最低实际可用推理强度；控制超时、重复与失控循环不是另设费用障碍。
- pi Provider 首先 DeepSeek；通用 API/百炼不自动一起启用。
- Codex 模型偏好 GPT-5.6 Luna；Kimi 偏好 K2.7；精确 ID 与 effort 由受控探测确认。
- 用户已提供凭据位置，只需受控本地加载，禁止索要正文。
- 业务目录全范围授权；实际验收仍优先新建临时项目，不修改无关资产。
- SSH、Ubuntu/远程：DEFERRED_BY_USER，非本地联调依赖。
- Codex 账号切换与重启：按用户本轮要求恢复到验收范围，但必须最后、独立 DUT 实例。

## 授权不包含什么

- 不包含读取/替换/注销当前 hzxpro 开发会话的凭据。
- 不包含关闭当前承担开发的 Codex 进程。
- 不包含全盘修改 ACL、关闭沙箱、防火墙或安全软件。
- 不包含让 Agent 任意上传源码、令牌、日志或屏幕内容。
- 不包含删除用户源凭据、账号目录或其他已有资产。
- 不包含自动 GitHub 发布、远程部署、main 合并。

## Codex 切号范围的变更

历史 H-01 的 EXCLUDED_BY_USER 改成 INCLUDED_LAST_DUT_ONLY。
可在已安全登记的两个独立 DUT Profile 间切换；不能把开发账号当前令牌复制给多个并发进程。
若 DUT 缺少第二个安全登录会话，只该用例标为 WAITING_USER_CREDENTIAL_SESSION，不阻塞 pi/Kimi、生产代码、Mock 切号失败注入等其余工作。
若用户实际要重启当前开发 Codex 应用，需另一个确定性监督器和用户的具体时点确认；不默认把它包含在 DUT 重启中。

## 可自动处理 / 只在必要时请求用户

自动：探测无秘密版本、写代码、假凭据检查、授权测试目录、生产注册、已批准 Profile 的最小调用、真实 UI 测试、故障复现、修复与回归、脱敏提交。

单点人工：操作系统 UAC/安全授权；独立 OAuth 登录；必须使用可见桌面而当前未解锁；创建新 OS 测试身份需要管理员批准；不能隔离时需另一个用户/VM。

这些请求必须具体，不再发“请补预算、SSH、账号和时间”的整张 H-01 问卷。
