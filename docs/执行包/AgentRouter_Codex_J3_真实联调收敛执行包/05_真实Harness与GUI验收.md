# 最小任务，覆盖真实路径

## 固定测试任务

在专用小目录放 input.txt，内容为公开的三行数字。执行角色读取、计算一个确定值，将结果写入 result.txt 并登记不可变产物；复核角色验证字节/哈希和计算；最后由指定角色把简短结论交给用户。

- 不让 Agent 分析整个 AgentRouter 源码来做 smoke test。
- 不重新把“只回复 OK”的直连 API 当 pi 测试。
- 输出文字尽量短，但工具调用 JSON 需要完整预算；不能把所有 Harness 限成 16 tokens 导致协议被截断。
- 对支持参数的适配器采用最低实际 effort、适量输出上限和墙钟超时；未支持参数记录不可配置，不假装生效。
- 单一不变错误最多进行有限次诊断性重现；推荐 2 次后必须做明确修复或提交最小人工作用请求。
- 费用不限不等于无限循环；自动链路有 hop、时间窗口、总时长和取消保障。

## 先三个单体验收

顺序：pi+DeepSeek → Kimi Code → Codex。
每家都要证明：实际进程/版本、脱敏身份与模型、会话开始、文件/工具操作、真实 Route 工具、结果交付、原生收尾、同账号进程重启后继续原角色。
其中任何一家缺少独立安全认证会话，只阻塞那一家；不重复询问全部账号/预算/SSH。

## 六条有方向边，之后一条联合链

至少分别观察：pi→Kimi、Kimi→pi、pi→Codex、Codex→pi、Kimi→Codex、Codex→Kimi。
可用两个有严格终点的小链覆盖，但每条边都要有真实发送/接收、task/message/native run 关联；不能用 UI 画线或调用 Mock route 代替。

联合链：用户→pi(执行)→Kimi(复核)→Codex(交付)→用户。
断言：同组内、各自独立上下文、正确产物版本；有且只有指定用户交付；不自动抄送原发起者；终态前下游保持等待。

## 故障与边界

- 同角色两项新任务 FIFO；当前任务关联结果可续办。
- 不同工作区并行；共享目录写互斥。
- 真实协议取消，与“本地把状态写成 cancelled”分开。
- 启动前失败不派下游；发送后失联进入待核对，不重复操作。
- Harness 崩溃/Core 重启/GUI 关闭重新打开分别测试。
- 历史回放不重新执行 Route 工具；旧 epoch、重复通知不能污染新运行。
- 注入网络错误用 Mock Provider 或专用代理，不修改整机网络影响开发会话。
- 无损失地记录模型/额度未知、登录失效、轮次失败；不需要耗尽真实额度来测试限额错误。

## Computer Use 与自动化

先用协议/进程测试和 Playwright/Electron 断言验证可重复逻辑。原生目录/保存对话框、托盘、缩放、窗口退出等再使用实际可用的 Computer Use/UI 自动化。

- 先确认当前 Codex 的插件和应用权限，不宣称调用了未安装工具。
- Windows 前台 Computer Use 会占用活动桌面，目标窗口应可见；必要时发一条“保持桌面可用”的具体请求。
- 不用 Computer Use 代替对安全设置的授权，不操作 UAC/隐私批准，不控制当前承担开发的应用。
- 凭据文件不得在编辑器里打开；Secret 在屏幕上时不得截图。事后打码不能撤回已经发给模型的截图。
- 自动点击测试记为真实 UI 自动化，不冒充人类可用性测试；对话框 stub 仍标为 stub。

## 收尾产物

实际安装候选包运行同一生产入口；打包目录白名单排除账号、.local 原始数据、原始日志、SSH 材料和用户项目正文。
未实现 SSH 继续标记延后，不能把 Windows 本地通过扩大成跨平台 V1.0 全部通过。
