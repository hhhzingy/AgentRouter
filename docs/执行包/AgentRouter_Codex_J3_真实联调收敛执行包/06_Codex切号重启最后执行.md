# J3-06：Codex 切号与重启——最后，独立被测实例

## 先区分两种 Codex

开发控制实例 DEV：当前 hzxpro 会话，继续开发。不得终止、登出、替换其认证或搬走其会话。

被测实例 DUT：由 AgentRouter 注册和启动，使用专用持久 CODEX_HOME 与可识别进程。用户要测试的是 Router 控制它的账号和生命周期。

不能让开发 Agent 先关闭自己，再指望它继续执行后续脚本。必要的关闭/换文件/启动过程由独立确定性监督器完成。

## 预置条件

1. 安全 Gate 已通过；两个可用的、独立登记的 DUT Profile，代号可以为 A_TEST 与 fj。
2. A_TEST 若对应 hzxpro，必须是独立安全登录会话，不读取/复制当前 DEV 使用的令牌链。
3. 用户提供的 fj 文件视为导入种子，仅由受控助手本地读取；不得打印、截图或提交，且不得默认为长期有效。
4. 核对 DUT 确实采用文件凭据后端；否则改文件不代表实际认证改变。
5. 相同 DUT 运行目录持续保留对话；Profile 凭据副本与原生会话/项目数据分开。
6. 固定保护列表：DEV 与其子树；目标 PID 同时核验创建时间、执行路径、运行目录、监督器身份，防止 PID 复用误杀。

## 为什么不是简单复制开发 auth.json

官方认证说明要求保留刷新后的 auth 文件，并避免多台机器或并发任务共享同一认证副本。独立目录不自动产生独立令牌会话。
若第二个安全会话缺失，请求一次独立登录；其余调试继续。不要为保持“全自动”冒险干扰 DEV。

## 顺序

R1 同账号正常重启：A_TEST 创建 thread，完成一个小任务→停止 DUT→同 HOME 启动→恢复线程→继续一次工作。

R2 A_TEST→fj：
- 停止新派发；等待可确认的安全边界。
- 保存任务、会话、产物与切换意图。
- 只停止 DUT，确认相关子树停止；失败则不替换。
- 受控保存旧 Profile 最新刷新状态。
- 将 fj 最新凭据安全置入 DUT auth 文件，不改 DEV 文件。
- 启动新 DUT，通过 account/read 等原生身份接口核验；日志只保留脱敏匹配结果。
- 重新读取模型/推理/额度；身份不匹配或模型不可用即保持暂停。
- 恢复会话并运行小任务；验证一次且只有一次交付。

R3 fj→A_TEST：相同顺序，使用 A_TEST 最近刷新后的文件，不回填最初导入的旧种子。

R4 故障测试：目标认证失效、文件替换失败、进程未停、身份不符、切换中监督器退出、会话无法恢复。尽可能使用假凭据/模拟故障，不人为撤销日常账号。

## 会话连续性的证据

分别报告：角色 ID、Router 历史、原生 thread、当前任务、工作区、产物和队列是否保留。
先前小任务可在会话中写入一个非秘密标记，恢复后读取，用来验证不是偷偷新建空对话。

若平台拒绝跨账号恢复同一原生会话，不可宣称无损切换成功。保留旧会话，用明确交接创建新会话，并把“原生连续性未满足”作为能力限制单列。

## 哪种“Codex重启”算通过

- DUT App Server/CLI 进程重启：本包范围。
- AgentRouter GUI 关闭重开：单独用例。
- 当前开发 Codex/ChatGPT 桌面应用整体重启：不是以上两项的同义词，需最终明确时点和外部监督器/人工操作，不能自动扩张。

## 禁止

禁止按进程名 taskkill 全部 Codex；禁止覆盖用户默认 HOME；禁止让普通模型决定用户名或 auth 路径；禁止用 AI 自述“我是 fj”代替 account/read；禁止把残留进程状态未知当已关闭；禁止把自然刷新导致 auth 哈希变化当切号成功或被破坏的唯一证据。
