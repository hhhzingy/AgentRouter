# 不依赖“AI 不会记住”的秘密保护

## 工作目标

模型、模型可调用的文件/命令工具、GUI、仓库和发布包都不接触原始 Secret。可信的本地认证进程可以将认证材料发给指定服务；这与把它写入 Prompt/工具结果不是一回事。

## 当前用户目录处理

用户给出的“账号信息”目录只作为输入来源登记；原件不删除。目录未 Git 跟踪和路径禁止暂存是必要保护，但不能阻止普通文件读取、截图或网络上传。

推荐通过受控导入复制到项目/构建边界之外的受保护存储。如果用户要求仍放在 AgentRouter 内，也必须专用 ACL/身份隔离，并被 Git、扫描上下文、构建、备份、诊断、打包全部排除。不得把 .local 或 .gitignore 当 OS 沙箱。

## 可信本地助手

- 审查源代码后，先用假凭据验证它的所有输出；再执行真实读取。
- 只解析用户明确指定的材料，不递归读取全部账号目录。
- stdout/stderr/异常只输出 profile_exists、identity_match、auth_backend、readable_by_tool=false 等 allowlist 字段。
- 不输出 token 前后缀、refresh token、Cookie、Authorization、解码 JWT 或带认证的 URL。
- 不让子 Shell 继承长期 API Key 环境变量；需要注入时使用受控边界和实测隔离。
- Broker 的程序、配置和授权清单也必须受保护：未信任 Agent 工具不能改写这些文件后再借受信任进程读取秘密。绑定经过审查的构建摘要，更新时重新批准受信任边界。
- Broker 如用于 pi，只允许批准的 endpoint/模型/路径；不是“任意 URL 代理”。
- 通用 API 是第三方网关时，明确它可以接触请求内容。不能称为官方直连，也不能将 Codex/Kimi 的 OAuth 凭据交给它。

## 工具边界与网络

业务“全目录授权”不自动授予凭据读取、数据库管理、监督器或 `.ssh` 访问。测试使用新建的小工作区。

限制不可信工具出网与上传通道；Harness 向批准 Provider 的正常推理流量单独允许。若其他通道如 Web、MCP、浏览器能外传，也必须分别检查。

## 证据与版本控制

- 测试证据先本地 allowlist 构造，再扫描，再逐个暂存。
- 不采用 git add . 全目录打包运行数据。
- 真日志、HTTP 原文、屏幕截图先确认无敏感内容；默认禁止采集秘密页面。
- 假 Provider 测试可捕获合成请求；真实调用只保存必要元数据，不用解密代理收集鉴权正文。
- 阶段报告不包含真实账号邮箱、Key 内容、用户目录清单。
- 扫描覆盖 staged、相关历史、受控日志、构建与发布包清单，不能因 staged 清洁就宣布全系统零泄漏。
- 假 canary 字符串仅留隔离测试区；不得将真 Key 作为模型可见的“搜索关键词”。

## 如果发现泄露

停止相关上传/发布；保留脱敏事故证据；立即请求或通过已批准机制撤销/轮换受影响 Secret；再处理 Git 历史、CI 产物、日志和缓存。删除当前文件或把仓库设为私有不等于旧凭据安全。

## 准确的安全声明

“在所测版本、账户会话和权限配置下，未发现秘密进入模型内容、工具结果、仓库与发布包；负面访问试验由 OS 拒绝。”
不是“AI 绝不会记住”“.gitignore 保证不会泄漏”或“阻止所有管理员/恶意软件”。
