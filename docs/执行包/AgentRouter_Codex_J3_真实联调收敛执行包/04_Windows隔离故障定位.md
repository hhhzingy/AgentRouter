# J3-02：把模糊 BLOCKED_ENV 变成可定位结果

## 先修探针，而不是放宽整个 Agent 权限

当前 AccessCanary.cs 同时设置 owner 与 DACL，且只在当前线程模拟受限 token。先完成以下小步，每步输出阶段、HResult/Win32 error、耗时和布尔结果，禁止输出真实凭据：

1. 在全新测试目录检测卷类型和 ACL 支持、进程 principal/组/完整性级别（共享报告脱敏）。
2. 读取新目录所有者和访问权限元数据；确认能创建、读取、写入普通测试文件。
3. 将 DACL 设置与 owner 变更拆成独立测试。不需要改变 owner 的路径不要附带 SetOwner；这不是放宽被测权限。
4. 比较当前受控开发 Shell 和普通独立 PowerShell 的结果。只有实际工具权限不允许时，向用户请求运行已有无秘密脚本一次。
5. 如确需管理员初始化，仅运行经过审查、作用于新测试根的安装步骤；用户批准 UAC，AI 不代点。
6. 每次输出唯一 run_id 和独立目录；全程 watchdog，broker 失败时清理自己创建的 PID；不删除已有用户目录。

## 不能将线程 impersonation 当完整沙箱

当前探针可以验证一组 AccessCheck，但不等于未信任的 Shell 进程已被限制。
实际被测执行必须使用受限 primary token/独立低权限账号/经过验证的 OS 沙箱；子孙进程继承边界；持有秘密的 broker 不运行在不可信工具上下文中。
测试不能仅以 ReadAllText 报错为依据：必须正向证明授权测试文件可以读写，同时反向证明秘密区域不可读写、不可重设 ACL、不可经父进程句柄/环境/内存/重解析点绕开。

## 建议隔离对象

- 开发 Codex 的日常认证、会话、配置：只保留原进程使用，测试工具不可访问。
- 受保护 Profile/Broker：允许可信运行器使用凭据，不向 Agent 工具返回秘密。
- 被测工作区：新建小项目，工具可完成验收需要的读写。
- AgentRouter 控制数据：数据库、内部认证、监督器控制口不能因“目录全范围”向工具开放。
- 诊断、截图、Prompt、产物：永远不接受原始 Secret。

另一个 CODEX_HOME 只是目录隔离，不是权限隔离。若相同 OS 权限仍可读整个磁盘，不能声明硬隔离。

## Gate 最小组合（全部要求正/负控制）

A. Broker 能执行一次受控认证操作；返回只有 profile/identity_match 等布尔元数据。
B. 工具能读写授权 dummy 工作文件。
C. 工具读/写秘密 canary 被 OS 拒绝；工具无法自行修改保护。
D. 子孙进程同样受限，环境和命令行不携带长期 Key。
E. 模型工具不能调用 Core 管理接口或冒充监督器完成运行。
F. Mock Provider 捕获的消息正文、工具结果不含 canary；鉴权材料只在认证边界。
G. 非允许目标的外传被拒绝；无法实现时降低声明，不能隐藏缺口。
H. 真实日志不记录正文/认证头；canary 扫描、包内容清单和截图安全通过。

这些 Gate 证明指定版本/配置/威胁模型下的边界，不是对管理员、恶意原生 Harness 或已攻破 OS 的绝对保证。

## 环境仍受阻怎么办

按顺序尝试新 NTFS 测试根、普通终端验证、明确的受限进程方案；必要时使用独立 Windows 用户或 VM。不要默认需要另一台机器，也不要在沙箱内无限重复同一失败。
一次提出所需的最小用户动作，继续其他可执行工程工作。
