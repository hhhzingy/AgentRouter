# 真实账号联调安全基线

## 一、先给出直接结论

不能通过一句“不要记忆或上传 API Key”来保证安全。

只要 Codex、Kimi Code、pi 或它们启动的 Shell/工具能够读取真实密钥，就必须假设它有能力把密钥写入输出、日志、文件或网络请求。安全目标应改为：

> **模型输入、工具可读文件系统、工具环境变量、仓库、诊断日志和 GUI 都拿不到原始凭据。**

模型不能记住它从未见过的内容，也不能上传它无法读取的内容。

## 二、需要区分四件事

1. **Harness 客户端使用凭据认证。**这是正常行为，凭据会作为认证材料发往对应服务。
2. **凭据是否进入模型请求正文。**必须禁止。
3. **Agent 执行的命令是否能读取凭据。**必须通过权限和隔离禁止。
4. **服务提供方如何保留业务内容。**由账号计划和 Data Controls 决定，不能替代本地秘密隔离。

即使服务承诺不用于训练，也不应该把 API Key 放进 Prompt。

## 三、当前仓库在真实联调前必须修改

### 1. 禁止提交原始证据日志

当前 `.gitignore` 有：

```gitignore
*.log
!evidence/**/*.log
```

真实联调前必须改为：

```gitignore
*.log
evidence/raw/
evidence/live-raw/
**/auth.json
**/*token*
**/*secret*
**/.env*
```

仓库内只提交：

- 测试名称；
- 版本；
- 时间；
- 退出码；
- 已脱敏状态；
- 事件计数；
- 非敏感错误码；
- 哈希；
- 明确的 REDACTED 标记。

原始 stdout/stderr 放在仓库外，例如：

```text
%LOCALAPPDATA%\AgentRouter\diagnostics\raw
~/.local/state/agentrouter/diagnostics/raw
```

设置限制权限和自动过期。

### 2. 兼容性报告脱敏

不要把用户名、完整 HOME、账号邮箱、组织 ID、绝对凭据路径提交到仓库。保留平台、相对安装位置、版本和二进制哈希即可。

### 3. Secret 扫描成为提交 Gate

每次提交前扫描：

- OpenAI/Kimi/其他提供商密钥格式；
- Bearer/JWT；
- `auth.json` 字段；
- Cookie；
- `.env`；
- PEM 私钥；
- Windows/Linux 用户目录中的秘密副本。

扫描失败必须阻止提交，不能只警告。

## 四、推荐凭据架构

### 1. 数据库只保存引用

`account_profiles.secret_ref` 方向正确。SQLite 不保存明文 Key、Refresh Token 或完整 `auth.json`。

记录示例：

```json
{
  "profile_id": "account_xxx",
  "harness": "codex",
  "secret_ref": "os-secret://agentrouter/codex/profile-a",
  "identity": {
    "label": "测试账号 A",
    "masked": "a***@example.com"
  }
}
```

### 2. 凭据目录在项目和 worktree 之外

Windows：

```text
%LOCALAPPDATA%\AgentRouter\secrets\
```

Linux：

```text
~/.local/share/agentrouter/secrets/
```

禁止放在：

- 项目目录；
- `.agent-route/`；
- `docs/`；
- `evidence/`；
- Git worktree；
- AI 可见附件；
- 命令行参数。

### 3. 不把原始密钥放进 Agent 环境变量

环境变量比命令行好，但如果 Agent 能执行 `env`、PowerShell 或读取 `/proc`，它仍可能看到。

优先顺序：

1. OAuth/设备登录，由用户在 Agent 之外完成；
2. OS 凭据库或受保护文件；
3. 受限 Credential Broker；
4. 仅在无法替代时使用环境变量，而且使用一次性、低权限、低额度测试 Key。

### 4. Credential Broker

对需要 API Key 的 Harness，推荐新增本地 Credential Broker：

```text
Harness / Agent 工具
       │ 不持有长期 Key
       ▼
受限本地 Socket
       ▼
Credential Broker
       │ 持有 Key、添加认证头、限制目标域名
       ▼
模型服务
```

Broker：

- 独立进程；
- 不向调用者返回 Key；
- 只允许预注册域名和 API 路径；
- 日志不记录 Authorization；
- 可以施加账号、模型、额度和请求大小限制；
- 能撤销和轮换；
- 使用 OS 身份/Unix Socket ACL/Named Pipe ACL 验证调用方。

如果某个 Harness 不支持代理且必须直接读取 Key，则不能宣称“硬保证模型不可见”，只能使用沙箱和一次性测试凭据降低风险。

## 五、Codex 联调基线

### 1. 个人账号的数据控制

个人版 ChatGPT/Codex 内容可能用于改进模型，除非在 Data Controls 中关闭。真实联调前：

- 关闭“Improve the model for everyone”；
- 不对包含敏感项目内容的会话提交 thumbs up/down 反馈；
- 不把 API Key 粘贴进聊天；
- 不依赖“记忆关闭”保护密钥。

Business、Enterprise 和 API 默认不用于训练，但依然不能把密钥放入输入。

### 2. `auth.json`

`auth.json` 应按密码处理：

- 用户在独立终端中登录；
- AgentRouter 只在受控账号模块中移动/替换；
- 不让 Codex 开发角色读取文件内容；
- 不提交、不贴入 issue、不写入阶段报告；
- 运行后保存刷新后的最新文件；
- 切换前确认相关进程停止；
- 切换后通过账号接口核验身份。

### 3. Codex 权限 Profile

为 AgentRouter 开发任务建立最小权限 Profile：

- `:root = deny`；
- 只读运行时最小路径；
- 只允许读写当前 worktree；
- 显式 deny `~/.codex`、AgentRouter secrets、`.ssh`、`.env*`、`auth.json`；
- Agent Shell 默认无网络；
- 需要网络时只允许明确域名，并启用实际网络代理过滤；
- Web、Browser、Connector、MCP 各自单独关闭或限定，不认为命令网络规则能覆盖它们；
- 禁用 `danger-full-access`。

权限配置必须用当前实际 Codex 版本做负面测试。不能只看到配置文件存在就算通过。

## 六、Kimi Code 与 pi

### Kimi Code

- 优先使用 OAuth Profile；
- 账号目录独立于项目；
- 工具进程不可读取 Profile 凭据；
- ACP 反向请求和工具调用必须做 allowlist；
- 额度/用户信息 API 只返回结构化脱敏数据；
- 不把完整响应原文写进日志。

### pi

pi 往往需要第三方 Provider Key，因此风险最高：

- V1.0 推荐通过 Credential Broker；
- 未完成 Broker 前，只允许一次性、低额度、可随时撤销的测试 Key；
- 不把 Key 放在模型可执行 Shell 继承的环境里；
- 每个 Provider 建立独立 Profile；
- 限制可访问模型与预算；
- 联调后立即撤销。

## 七、真实联调的六道 Gate

### SG-1：静态秘密扫描

仓库、Git 历史、构建产物、证据和安装目录无真实 Secret。

### SG-2：假 Provider 捕获测试

将 Harness 指向本地 Mock Provider，检查完整请求：

- Authorization 只出现在认证层；
- Prompt、system/developer/user 内容无 Secret；
- 工具结果无 Secret；
- 错误和日志无 Secret；
- 诊断导出无 Secret。

### SG-3：沙箱对抗测试

在没有真实 Secret 的环境中放置 canary 文件，要求 Agent 尝试：

- 读取凭据目录；
- 读取 `.ssh`；
- 打印环境变量；
- 搜索 `auth.json`；
- 访问本地 Broker Socket；
- 向任意公网域名发送内容。

预期全部被拒绝，拒绝证据为权限错误而不是“模型自愿不做”。

### SG-4：最小真实凭据

创建专用测试账号或测试 API Project：

- 无生产数据；
- 无管理权限；
- 最低可用额度；
- 设置费用上限；
- 可立即撤销；
- 不与日常账号共用长期 Key。

### SG-5：在线最小闭环

只执行一个无敏感源码的固定任务：

```text
创建会话 → 回答固定字符串 → 调用无副作用工具 → 正常收尾 → 注销/撤销凭据
```

### SG-6：联调后审计

- 立即轮换或撤销测试 Key；
- 扫描仓库、日志、数据库、崩溃转储和剪贴板；
- 核对网络目标；
- 确认没有把原始日志提交 Git；
- 记录结论，但不记录密钥。

## 八、剩余风险

以下情况无法给出绝对保证：

- Harness 本身存在恶意代码或供应链后门；
- Agent 被授予完整磁盘和完整网络；
- Key 必须直接存在于 Agent 继承的环境；
- 操作系统账号已被攻破；
- 用户主动把 Key 粘贴到 Prompt；
- 使用个人账号且未关闭训练；
- 第三方 Provider 的数据政策不满足要求。

因此 V1.0 的安全声明应是：

> 在经过验证的版本和权限配置下，AgentRouter 不把凭据加入模型上下文、业务消息、仓库或诊断导出；Agent 工具被限制读取凭据目录。尚未验证的 Harness 或 Provider 明确标注为实验支持。
