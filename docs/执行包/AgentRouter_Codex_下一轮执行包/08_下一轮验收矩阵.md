# 下一轮验收矩阵

## G10：合同与安全基线

| ID | 验收项 | 通过标准 |
|---|---|---|
| G10-01 | Client API C1 | Schema、生成类型、Mock 和文档一致 |
| G10-02 | 写操作幂等 | 重连后相同 operation 不重复 |
| G10-03 | 控制租约 | observer 无法写 |
| G10-04 | capability | 未实现功能不会被 UI 当作可用 |
| G10-05 | Secret 日志 | raw 不进入 Git，redacted 输出可验证 |
| G10-06 | Secret 扫描 | canary/测试 secret 触发阻断 |
| G10-07 | context 最小披露 | section 只返回请求内容 |
| G10-08 | notice | 持久化、目标可见、不唤醒 |
| G10-09 | SQLite 策略 | 支持安全版本范围，不精确锁单版本 |
| G10-10 | UNKNOWN API | 可审计地核对和解除，不直接改库 |

## G11：独立 Core

| ID | 验收项 | 通过标准 |
|---|---|---|
| G11-01 | 无 GUI 启动 | Core 作为服务独立运行 |
| G11-02 | 全量管理 API | 项目、空间、角色、任务、Run、结果可操作 |
| G11-03 | Mock Adapter | 完整生命周期，不只是终态 mapper |
| G11-04 | Event Stream | 单调 cursor，可 catchup |
| G11-05 | GUI 断开 | 任务继续，状态持久 |
| G11-06 | Core 重启 | 活跃 Run 进入对账，不重跑 |
| G11-07 | 错误可见 | stderr/异常进入诊断和 issue |
| G11-08 | Outbox | HELD/QUEUED/UNKNOWN 状态正确 |
| G11-09 | Artifact retention | 引用存在时不被清理 |
| G11-10 | Backup restore | 新目录可恢复并通过完整性检查 |

## G15：三 Harness

每家都需要分别证明：

- 版本锁；
- 创建会话；
- 恢复；
- Prompt；
- 对话事件；
- Route Tool；
- 权限请求；
- 取消；
- 原生 settle；
- 断线；
- UNKNOWN 对账；
- 日志脱敏；
- 账号身份；
- 额度状态；
- 不重复历史工具调用。

任何一家未通过，不计入真实支持数。

## 发布规则

- G10—G13 未通过：不得开始真实账号；
- G14 未通过：Codex 真实支持数仍为 0；
- Codex 通过不代表 Kimi/pi 通过；
- 三家 Probe 通过不代表三家 Adapter 通过；
- 模拟 E2E 不替代真实进程 E2E；
- 私人仓库不等于 Secret 可以提交；
- V1.0 发布前仍需原 81 项产品验收与新增远程功能验收。
